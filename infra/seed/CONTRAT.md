# Le contrat des données de démonstration

Les données du fil rouge (le réseau de médiathèques de Valmorin) se chargent **sur le schéma que tu écris** au lab `schema`. Pour qu'elles passent, ton schéma doit respecter ce contrat. C'est un fait métier : il te dit ce qui existe, pas comment l'écrire.

## PostgreSQL (base `valmorin`)

| Table | Colonne | Ce que contiennent les données |
|---|---|---|
| tous | `id` | entier, posé par les données ; ta colonne doit l'accepter : `generated by default as identity` |
| `site` | `nom`, `ville` | textes de 30 caractères au plus ; 6 sites |
| `adherent` | `numero_carte` | `VAL` suivi de 6 chiffres, unique |
| | `nom`, `prenom` | 30 caractères au plus |
| | `email` | 60 caractères au plus, unique |
| | `telephone` | 10 chiffres, **parfois absent** |
| | `date_inscription` | une date |
| | `site_id` | le site d'inscription |
| `auteur` | `nom`, `prenom` | 30 caractères au plus |
| `ouvrage` | `isbn` | 13 chiffres, unique, **parfois absent** |
| | `titre` | 80 caractères au plus |
| | `annee` | une année entre 1950 et 2025 |
| | `editeur` | 30 caractères au plus, **parfois absent** |
| `ouvrage_auteur` | `ouvrage_id`, `auteur_id` | 1 à 3 auteurs par ouvrage, jamais deux fois le même |
| `exemplaire` | `code_barre` | `EX` suivi de 8 chiffres, unique |
| | `etat` | `neuf`, `bon`, `abime` ou `retire` |
| `emprunt` | `date_emprunt` | une date entre le 1er octobre 2021 et le 30 septembre 2026 |
| | `date_retour_prevue` | 21 jours après l'emprunt |
| | `date_retour` | jamais avant l'emprunt, au plus tard le 15 octobre 2026, **absente** si l'ouvrage n'est pas rendu |

« Aujourd'hui », dans le fil rouge, c'est le **15 octobre 2026**.
